What is this

          
Sentence Reader is a local user interface for navigating annotated corpora from the ACoLi GitHub repositories. It is one piece of a proposed ACoLi NLP Toolkit.

          
You can open catalogued resources, move through sentences, and inspect what each file actually provides: word form, lemma, morphology, part of speech, named entities, dependency arcs, and constituency trees when those layers exist. You can also export the current view for reuse elsewhere.

          
The tool is built to grow in three directions: more corpora beyond the current ACoLi set, more reading and analysis features as the toolkit expands, and an open-source release so others can download it and run it on their own machines.

          
Lab Hub build, October 2026. Each corpus keeps its own license; local use follows those terms.

Dependency

          
Dependency describes how words attach to each other. Each token may point to a head and carry a relation label. The reader does not claim one universal tree for every file. It shows what the source supplies, and labels how that view was produced. When a tier applies, it appears beside the mode controls and as a letter tag (D1 to D4). Details for a selected word are in the word panel.


          
D1 Annotated

          
What it means

          
The corpus already contains gold dependency annotation: heads and relation labels written in the file. You are looking at the published structure, not a guess.

          
How it is done

          
The reader reads HEAD and DEPREL (or equivalent columns), lays out the arcs, and leaves labels unchanged. No remapping and no induction. Typical of many UD-style CoNLL-U releases.


          
D2 Mapped

          
What it means

          
The attachment structure is still gold from the file, but the relation names come from another inventory (for example PROIEL-style labels). The reader shows a UD-style label for easier comparison across sources, while remembering what the file originally said.

          
How it is done

          
Heads are kept as published. Relation bases are mapped into a common UD-style set (for example pred to root, sub to nsubj). Unknown bases stay visible in a safe form. The native label is stored alongside (for example in provenance fields) so you can inspect both the mapped view and the original wording.


          
D3 Induced

          
What it means

          
There is no gold dependency layer, but there is a gold constituency PARSE (common in ReM). The dependency picture you see is derived from that phrase structure. It helps you explore attachments; it is not gold Universal Dependencies.

          
How it is done

          
PARSE brackets are read into a phrase forest. Head percolation picks a head word inside each phrase using simple head rules. Other words in the phrase attach to that head. The forest root becomes the sentence root. Labels are coarse. Per-token provenance can record the phrase path and the rule that chose the head.


          
D4 Weak baseline

          
What it means

          
There is usable part-of-speech information, but no gold or induced dependency tree to trust. The arcs are a demonstration scaffold only, not linguistic annotation.

          
How it is done

          
The reader picks a simple root (often the first verb-like token with a surface form, otherwise a content word) and attaches the remaining tokens to it with a baseline relation. Use this only to see that tokens exist in a graph layout.


          
If none of D1 to D4 applies, dependency mode stays off. That empty case is not shown as a letter tag.

        

        

          
Constituency

          
Constituency describes phrase structure: how words group into larger units. The reader follows what the file provides instead of forcing every sentence into a phrase tree. When a tier applies, it appears beside the mode controls and as a letter tag (C1 or C2).


          
C1 Annotated

          
What it means

          
The file contains gold constituency annotation, usually as PARSE brackets (typical of ReM). The tree you see is the published phrase structure.

          
How it is done

          
The reader tokenizes the PARSE cells, rebuilds the bracketed forest, and draws it as a constituency tree. Labels and nesting stay as in the source. No projection from dependencies is involved.


          
C2 Projected

          
What it means

          
There is no gold PARSE, but there are trusted dependency heads from D1 or D2. The constituency view is an illustration built from those heads so you can see grouping in a phrase-style layout. Nested or thin trees are expected. It is not a substitute for gold phrase annotation.

          
How it is done

          
For each head and its dependents, the reader wraps them into simple phrase nodes (for example NP, VP, S) and draws that tree. Projection uses only D1 or D2 heads. It never treats D3 or D4 fills as if they were gold structure to project from.


          
If there is no PARSE and no D1/D2 basis to project from, constituency mode stays off. That empty case is not shown as a letter tag.
